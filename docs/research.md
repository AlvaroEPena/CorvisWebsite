# Stack Research — Corvis (2026-10-07)

Archetype: static single-page marketing/lead-gen landing page with one server-side endpoint (contact form). No DB, auth, CMS, payments.
Versions verified 2026-10-07 with `npm view` (Node v24.21.0, npm 11.19.0 on this machine). Sibling research (grit 2026-10-05, zydeco 2026-10-06) was reused; only versions, Fonts API status and Turnstile limits were re-verified. Everything not marked (unverified) was checked today.

## Requirements that drive the choice

1. Lighthouse 95+ on mobile with a visually heavy "glass" design: ship the least JS, static HTML, optimized images, no CLS.
2. Glassy look (backdrop-filter, gradients, soft 3D objects) must stay fast on mobile and Safari; needs a degrade path.
3. Smooth scroll-triggered motion plus an interactive before/after slider, all respecting `prefers-reduced-motion`, with content visible without JS.
4. Contact form that really emails the owner, with validation and spam protection (privacy note, personal data), on Cloudflare free tier.
5. Content in code (typed data), SEO basics (meta, OG, sitemap, JSON-LD ProfessionalService), WCAG AA.
6. Windows 11, Node 24 + npm only, fewest accounts, consistency with sibling sites (mod-labs, grit, zydeco).

## Animation approach (GSAP vs CSS scroll-driven vs Motion)

- **Default layer: CSS.** Reveal-on-scroll, parallax of floating objects and the sticky nav glass fade can use `animation-timeline: view()/scroll()` (compositor-driven, 0 JS). Support is Chromium-led; Safari support recently arrived (believed Safari 26, unverified, confirm on caniuse at build time). Always wrap in `@supports (animation-timeline: view())` and keep the static final state as the fallback so content is never hidden.
- **GSAP + ScrollTrigger (3.15.0) only for:** the hero entrance timeline, pinned/sequenced "process" section if desired, and cross-browser parallax. Free for commercial use (standard license, sibling-verified). Register in one `src/scripts/motion/` module, import dynamically after first paint, wrap with `gsap.matchMedia()`. Animate transform/opacity only.
- **Motion (motion.dev 14.0.0):** lighter and fine for micro-interactions but weaker at timelines; do not mix with GSAP. Runner-up if the owner wants to drop GSAP.
- **No Lenis** (1.3.26): scroll hijack hurts a11y, anchor links and focus; native `scroll-behavior: smooth` under `prefers-reduced-motion: no-preference` with `scroll-margin-top` handles anchored sections.

## Image / 3D asset strategy

- Pre-rendered transparent assets beat WebGL for this brief: LCP is the hero text/gradient (not the canvas), no GPU cost, deterministic look in every browser. Produce 4 to 6 soft 3D objects (orbs, rounded cubes, glass slabs) as transparent AVIF/WebP at 1x/2x, each under ~40 KB, plus the OG image.
- Compose the rest in CSS/SVG: radial/conic gradient meshes for orange and deep-green panels, SVG noise grain (inline data URI, tiny) for premium texture, blurred pseudo-element blobs (blur on a static element is cheap; backdrop-filter on scrolling content is not).
- Portfolio and before/after placeholders: generate polished mock screenshots as SVG/HTML-rendered images once (Playwright screenshot script, `scripts/`), stored in `src/assets/`, so they can be replaced by real case studies by swapping files + data entries.
- Hero object(s): `fetchpriority="high"` only if they are the LCP element; otherwise keep LCP as the headline text (preferred) and lazy-load all below-fold images.
- Optional later: three.js 0.186.1 or a tiny raw-WebGL scene, lazy, with the static image as poster/fallback (same pattern as Zydeco). Not in MVP.

## Glass-effect performance pitfalls (mobile / Safari)

Sources below (WebKit/Mozilla bug threads, Apple forum, 2026 articles) plus engineering experience. Mitigations to bake into the spec:

1. **Limit the number and area of `backdrop-filter` layers.** Budget: at most ~4 to 6 blurred elements in the viewport at once on mobile, blur radius 12 to 20px (not 40+). Cost scales with blur radius and covered area.
2. **Never put backdrop-filter on large elements over scrolling or animating content** (known jank on mobile Safari, Firefox Android, mobile YouTube-style fixed bars). Fixed nav: acceptable but small; prefer a mostly opaque translucent fill with blur 8 to 12px.
3. **Do not animate elements that carry a backdrop-filter** (no transform/opacity transitions on the blurred element itself in large numbers; animate a wrapper or limit to few cards). Never animate the blur radius.
4. **Safari needs `-webkit-backdrop-filter`** alongside the unprefixed property, and CSS custom properties inside `-webkit-backdrop-filter` are not applied in Safari 18+ (reported); write literal values (Tailwind's `backdrop-blur-*` emits both; verify the output) or define the glass recipe in one CSS class with literals.
5. **Nested backdrop-filters and parent `overflow`/`border-radius`/`mask` clipping** produce flicker and missing blur in WebKit; keep glass cards flat in the DOM, avoid `will-change: transform` on ancestors, and avoid `overflow: hidden` + radius combos on the blurred element's parent where possible.
6. **Fallback tier:** `@supports not (backdrop-filter: blur(1px))` and `@media (prefers-reduced-transparency: reduce)` and a low-power/`saveData` check give a solid, higher-opacity panel with the same gradient border; text contrast must pass AA on both tiers. Test contrast on the worst-case background behind translucent cards.
7. **Contrast and legibility:** glass over pearl background risks low contrast; ensure text on glass uses dark-ink colors verified to WCAG AA, and add a 1px inner highlight/border rather than relying on blur for separation.
8. **Gradient/blur background blobs:** use pre-blurred raster/SVG or `filter: blur()` on small static elements; avoid large animated `filter: blur`. Keep `box-shadow` stacks modest.
9. **Measure:** run Lighthouse mobile (Slow 4G, 4x CPU) and a real-iPhone check before sign-off; Playwright WebKit project for visual regressions (optional).

## Alternatives considered

- **Next.js 16 static export / SvelteKit / React Router**: ship a framework runtime for a single page; no benefit, hurts Lighthouse and consistency.
- **Plain CSS instead of Tailwind**: viable (Refined Celebrations style); Tailwind chosen for consistency with Grit/Zydeco and speed of design iteration.
- **Motion 14.0.0 instead of GSAP**: see animation section.
- **React/Svelte islands for slider or form**: unnecessary; vanilla TS island is smaller and testable.
- **Formspree / Web3Forms / Netlify Forms**: extra vendor and a form-embedded third party for something a Worker on the same project handles.
- **Honeypot-only spam protection**: no extra account but weak; use as an additional layer, not the only one. reCAPTCHA/hCaptcha: heavier, privacy cost; Turnstile preferred and on the same Cloudflare account.
- **`@astrojs/cloudflare` adapter (14.3.4) with an Astro API route**: ties form handling to SSR build output; a standalone Worker with `run_worker_first` keeps pages purely static.
- **Cal.com/Calendly embed**: nice-to-have later; the "Book a free consult" CTA scrolls to the form (or `mailto:`/link) in MVP. Lazy-load any embed on click (facade) to protect Lighthouse.
- **Image CDN (Cloudflare Images/Cloudinary)**: unnecessary; few static images.
- **TypeScript 7.0.2**: blocked by `@astrojs/check` peers.
- **Lenis**: skipped.

## Risks / open questions

1. **Glass vs Lighthouse/battery on mobile Safari**: the signature look is the main perf risk. Mitigation: blur/area budget, fallback tier, pre-rendered 3D, real-device check, Lighthouse gate with a documented budget.
2. **Contact delivery depends on external setup** not yet available: owner email address and a verified Resend sending domain (Corvis domain not decided; Resend requires a verified domain to send). Until then the form runs in demo mode (success state without sending) via an empty endpoint, or deploy sender on a verified domain such as modlabs.store with owner confirmation.
3. New majors and peer lag (Astro 7, Vitest 5, ESLint 10; TS 7 blocked): pin TS 6, run all gates right after scaffold, commit lockfile. Safari scroll-driven animation support unverified: rely on `@supports` fallback.
4. Placeholder content (prices, testimonials, portfolio) must be clearly flagged as placeholder in data files and not presented as real claims; the JSON-LD must not include fake ratings/reviews.
5. Turnstile free-tier terms were verified today but could change; Resend free limits were last verified 2026-10-06 (zydeco research).
